# 发布清单

本文是维护者的验证清单，不代表项目已完成以下步骤。每次发布应记录版本、提交号、测试环境和实际部署结果；无法实测的平台须保留为未验证。

目标仓库：[863401402/sanview](https://github.com/863401402/sanview)。目标页面：[积木三视图实验室](https://863401402.github.io/sanview/)。1.1.0 的文档与变更记录日期为 2026-10-02。

## 备份与发布范围

- [ ] 确认从原服务器取回的原始源码归档已在本地留存，记录来源和校验信息；备份不提交 Git、不上传 GitHub，也不进入 Pages。
- [ ] 保留当前可回退的 Git 提交号及现有发布版本，不用本地工作目录整体覆盖线上站点。
- [ ] 检查待提交文件和 Git 历史，排除密钥、SSH 配置、环境文件、个人信息、原始备份及临时产物。
- [ ] 确认版本号、锁文件和 `CHANGELOG.md` 一致，README 截图来自当前实现。

## 本地质量检查

- [ ] 在 Node.js 20 或更高版本运行 `npm ci`；CI 使用 Node.js 22。
- [ ] 运行 `npm run check`，验证语法、纯逻辑和本地服务相关单元测试。
- [ ] 运行 `npm test`，完成单元测试与端到端测试。可安装 Playwright Chromium，或设置 `SANVIEW_BROWSER` 指向现有 Chrome 的绝对路径。
- [ ] 运行 `npm run build`，检查 `_site/` 包含应用资源与必要许可证，不含源码备份、测试结果或开发依赖。
- [ ] 使用 `npm start` 打开本地页面，确认默认只监听 `127.0.0.1:4173`；检查入口、脚本、样式与音频路径。
- [ ] 保存并检查实际桌面和移动端截图，更新 `assets/screenshots/desktop.png` 与 `assets/screenshots/mobile.png`。

## 核心学习流程

- [ ] 观察、练习、搭建平级且可直接使用，不要求身份选择、年龄限制或按顺序完成课程。
- [ ] “讲解提示（家长/老师）”为可选辅助内容；教程仅通过 `?` 按需打开，首次访问不自动弹出。
- [ ] 默认展示简单难度的三层台阶；“用这个模型练习”保留当前观察模型与空间尺寸并进入绘图，不替换为随机题。
- [ ] 手机逐幅选择正视图、左视图、俯视图后能回看模型；切换时保留已画内容，明确换题时才初始化图纸。
- [ ] 依次完成观察范例、画三视图、按三视图还原和自由搭建；核对三个范例与前、左、上方向。
- [ ] 验证边长 3、4、8 与四档难度；检查生成结构的边界和正下方支撑。
- [ ] 验证还原任务接受投影相同的不同合法结构，颜色不影响判题。
- [ ] 同题多次检查不增加题数；答错后答对更新原记录；查看答案后不计独立完成。
- [ ] 确认统计标为最近 200 题内记录，可供自己、家长或教师回顾，不显示考试成绩或能力诊断；清除练习记录不会删除作品。
- [ ] 验证自由作品自动保存、刷新后恢复，以及切换到观察或练习后作品仍保留。
- [ ] 验证 JSON 导出导入；越界、重复、悬空、错误版本和过大文件不覆盖原作品。
- [ ] 验证撤销、重做和新操作清空重做分支；缩小空间后撤销能够恢复尺寸与积木。
- [ ] 检查存储被禁用、存储配额不足或已有数据损坏时，页面仍可使用并给出相应保存提示。
- [ ] 使用键盘完成模式切换、画图和搭建盘操作；检查焦点、弹窗退出及触摸交互。
- [ ] 验证静音、语音失败回退、各模式教程和剖切；确认剖切不改变模型、投影或存档。

## 兼容性与隐私

- [ ] 记录本次 Chromium/Chrome 的版本及测试结果。
- [ ] 在有条件的真实设备上测试 Safari 和微信内置浏览器；没有实测就明确写“未验证”，不以响应式截图代替。
- [ ] 确认没有新增分析、广告或账号服务；如增加联网数据处理，先同步 `PRIVACY.md`。
- [ ] 核对生成语音时适用的 MiMo 条款与音频分发权利。
- [ ] 保留 [第三方声明](../THIRD_PARTY_NOTICES.md)、Three.js 与 OrbitControls 的版权和许可证；如发现凭据泄露，先吊销再清理引用。

## GitHub 与 Pages

- [ ] 设置仓库描述、主页、Topics；确认默认分支为 `main`，按实际 CI 作业名称配置需要的状态检查。
- [ ] 在 Settings → Pages 中选择 GitHub Actions，确认使用统一的 `.github/workflows/ci.yml`。
- [ ] 验证部署依赖同一次工作流的测试与构建成功，仅发布 `_site/`；不要另设可绕过测试的并行部署工作流。
- [ ] 核对 Pages 所需权限、环境及发布来源，检查本次 `main` 的完整 Actions 运行结果。
- [ ] 在最终 Pages URL 实际打开页面，检查脚本、MP3、截图和 favicon；完成一次练习及作品导入导出。
- [ ] 确认项目子路径 `/sanview/` 下的资源可加载，本机、原服务器与 Pages 的本地记录不会自动迁移。
- [ ] 按维护需要启用漏洞报告与依赖告警，核对安全报告入口。

## 发布记录与回退

- [ ] 按实际发布提交创建版本标签及 Release，附功能摘要、验证范围和已知限制。
- [ ] 如果发布验证失败，使用此前已验证的提交重新执行同一测试和部署流程，并记录回退原因。
- [ ] 后续如更新原服务器，先保留其当前部署备份，再只发布已验证的静态产物；GitHub Pages 发布本身不会同步原服务器。
- [ ] 收集独立练习、家长陪学、教师演示和自由空间探索中的反馈，优先处理方向理解、纠错反馈和触摸操作问题。
