# 界面与交互审查

更新日期：2026-10-03，对应 1.2.0。定位保持为通用三视图与空间探索工作台：观察、练习、搭建平级且独立可用。家长陪学、教师演示、学生独立练习和个人空间验证都是使用场景，不要求身份选择或固定课程。

本轮把桌面作为模型与投影对照的主工作台，手机保留完整功能。这个取舍是产品决定，不是根据“多数家长使用某种设备”的调查结论；当前没有这类占比数据。

## 依据与结论

上一轮审查记录包含 `artifacts/desktop.png`、`artifacts/mobile-practice.png` 和 `artifacts/mobile-build.png`：其中手机练习曾出现三张 8×8 网格连续堆叠、模型远离当前操作，以及文件按钮抢占主要操作层级的问题。1.1.0 据此增加了逐幅投影选择、回看入口与更清楚的操作层级。这些是历史问题来源，旧测试和旧截图不作为 1.2.0 已通过回归的证据。

本轮进一步只读检查了 `js/app.js`、`index.html`、`css/style.css` 与语音目录，重点追踪按钮含义和实际状态变化。确认的问题不只在视觉密度，还包括选择减少却增加、查看答案覆盖原稿、清空范围不明确、换题丢失内容，以及全屏时看不到反馈。改进应先让操作可预期、内容可恢复，再评价新手是否容易理解。

下面记录 1.2.0 的改动与验收要求，不声称新功能已经通过浏览器回归或真实使用者验证。最终命令结果、截图与部署状态由发布者填写到 [发布清单](RELEASE_CHECKLIST.md)。

## 本轮调整

| 已确认的问题或使用障碍 | 1.2.0 改进 | 本轮待确认的效果 |
| --- | --- | --- |
| 桌面显示增加/减少工具，但 3D 拾取与搭建盘按鼠标键覆盖所选工具，左键会强制增加 | 主键执行当前选定工具，右键仅临时减少，不改变工具 | 选中减少后主键确实减少；右键后工具选中态不变；3D、搭建盘、触摸与键盘激活一致 |
| `showAnswer` 把答案写入可编辑 DOM 并覆盖 `practiceDrawn`，原稿无法恢复，旧错误提示还可能残留 | 参考答案使用独立只读弹窗，保留正在填写的三幅图纸 | 开关参考窗口前后逐格一致，原图检查状态不与参考内容混淆，关闭可恢复焦点 |
| “重画”清空全部三幅，手机只见一幅时不容易预判，且没有恢复方式 | 改为明确的“清空三幅”并提供“撤销清空” | 能完整恢复刚清空的图纸；重新涂格或换题后恢复入口失效，不串入另一题 |
| 绘图时缺少明确的方向辅助入口，参考帮助与独立作答的边界不清楚 | 增加明确标示的辅助观察按钮，使用后把本题记为参考学习 | 使用前后能理解统计含义；关闭帮助、撤销清空及后续答对都不会抹掉辅助标记 |
| 初次接触者直接面对多个方向与操作，不易建立同一模型的投影对应关系 | 提供可选的同模型三方向入门演示，保持三大模式直接可用 | 演示每步只改变观察方向，随时可退出；不引入必修路线、身份选择或功能解锁 |
| 检查控件在模型工具栏，图纸与检查动作分离；手机需要往返长页 | 检查放在投影旁，保留逐幅选择与模型/投影往返 | 完成或修改图纸后容易找到检查；往返不重置图纸，手机可完整操作各模式 |
| 未完成作答时，尺寸、难度、练习类型、离开或新题操作会直接初始化状态 | 已有未完成作答时先确认，取消保持当前题目 | 对每种入口验证取消与确认；取消后题目标识、结构、尺寸、图纸及辅助状态均不变 |
| 操作与保存提示只在 `.stage` 外的顶部说明区，全屏无法看到 | 提示置于模型工作区内，保留可读文本与状态播报 | 原生全屏下能看见支撑失败、保存失败及缩小空间提示；修正后不留下误导性旧消息 |
| 教程称难度可循环、沿用左右页面位置，旧录音可能覆盖更新后的说明 | 帮助直接系统朗读当前步骤；其他预录反馈过滤依赖左右页面布局的变体 | 当前控件与文字一致；手机语音不指错位置；静音、系统朗读不可用和音频回退均不阻断操作 |

## 验证边界与后续观察

本轮没有开展真实家长访谈、儿童或其他使用者的可用性测试，也没有教学效果研究或设备占比调查。不能据此声称“大多数家长使用电脑”、已显著降低学习成本，或能够提升多少空间能力。未进行 Safari 真机或微信内置浏览器真机测试；Chromium 通过或手机视口截图都不能代替这些验证。

2026-10-03 已完成 Chrome 154.0.8037.93 的浏览器回归与截图审查，覆盖 1440×1000 桌面、390×844 和 320×740 手机触摸模拟、768×1024 平板触摸模拟。验证了默认桌面练习的三幅图与检查控件同屏、8×8 窄屏网格的末列实际触摸、工作台全屏、参考答案保留原稿、撤销清空、取消换题、辅助统计与键盘焦点。截图审查后已调整桌面网格密度并同步 README 图片，详细命令与证据见发布清单。

全屏目标由模型区域调整为整个工作台，避免放大后失去题目投影与检查按钮；涂改已匹配视图后立即清除手机标签上的勾号，切换练习类型后恢复新按钮焦点。这些问题来自代码复核与浏览器回归，不代表真实使用者研究结论。

后续可邀请使用者分别完成短任务：自行选择一个模式；用入门演示解释同一模型的三个方向；画图后查看参考再继续修改；清空并恢复；选减少工具后操作；取消一次换题；搭建后保存和恢复。家长或教师可另试一次共同讲解。记录是否找到入口、能否预判按钮作用、是否混淆参考与独立完成，以及手机往返是否打断思考。

若手机仍频繁往返模型和网格，再评估可展开的小模型对照区。是否需要增加常驻面板，应根据实际任务观察决定，避免用更多控件解决尚未确认的问题。

## 设计方向与仍需讨论的取舍

产品主轴是“同一个立体模型，可以观察、验证、推理和编辑”。功能入口按操作分类；家长、教师、学生无需先选择身份。主界面保留直接操作，可选讲解提示提供使用方法。

| 设计层面 | 当前判断 | 依据与取舍 |
| --- | --- | --- |
| 模式组织 | 观察、练习、搭建平级；当前观察模型可直接进入绘图 | 自动更换模型会打断正在进行的比较或讲解；也应保留另起随机题的自由 |
| 桌面对照 | 作为主工作台，优先让模型、投影和当前操作互相对照 | 三视图本身就是比较关系，应利用大屏的并列空间；这不意味着已有设备使用占比证据 |
| 手机作答 | 逐幅切换并保留图纸，检查紧邻投影，可往返模型，保留所有模式操作 | 大格子方便点按；代价是无法同时比较三幅完整投影。小模型预览的必要性仍需真实任务观察 |
| 视觉层级 | 模型与当前动作优先，作品文件和记录次之 | 保存、导入、导出等低频操作不应和检查、增减积木争夺注意力 |
| 反馈语义 | 区分漏填、多填、辅助观察、参考答案和独立完成 | 展示参考不覆盖作答，清空可恢复；消息在当前工作区可见。剖切只影响 3D 展示，完整投影不变 |
| 默认内容 | 简单台阶示范入场，可主动打开同模型三方向演示，也可直接进入任意模式 | 固定示范提供比较对象，演示帮助理解；经常创作的人仍可继续上次作品，不被迫重走教程 |

仍需向真实使用者确认主用设备、最常进入的模式，以及对辅助观察和参考答案的理解。这些信息决定后续如何平衡默认示范、最近作品与手机对照空间；当前不以未经调查的设备或年龄假设替代验证。

代码范围包括 `index.html` 的模式、投影和状态区域，`css/style.css` 的桌面、小屏及全屏布局，`js/app.js` 的工具拾取、参考展示、清空恢复、换题确认与教程播放，以及 `js/voice-library.js` 的预录语音描述。历史审查参考了 [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md) 的焦点、触摸目标、反馈与动态效果规则；本轮以具体代码证据和回归结果核对行为，不据此宣称完成真实使用者验证。
