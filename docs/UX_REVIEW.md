# 界面与交互审查

审查日期：2026-10-03。定位是通用的三视图与空间探索工作台，支持自主观察、画图练习、还原模型和自由搭建。家长是常见使用者，老师讲解、多人共用设备和个人探索同样成立；不应把所有人导入固定课程或闯关路线。

## 依据与结论

本轮依据现有代码、浏览器测试，以及实际读取的 `artifacts/desktop.png`、`artifacts/mobile-practice.png`、`artifacts/mobile-build.png` 截图进行检查。读取时，手机练习截图为 390 × 2180 像素：三张 8×8 网格连续堆叠，操作后面的视图时，立体模型已经离开视野；手机搭建截图中，三个黄色文件按钮也抢占了操作层级。桌面截图已有清楚的“模型与三视图”对照关系。

结论是有针对性地重设手机交互和操作层级，保留桌面的对照布局与现有配色。截图和代码检查可以发现布局、反馈、焦点等问题，不能替代真实使用者验证。上述截图是本轮读取时的状态，后续回归测试可能更新同名文件。

## 验证边界与后续观察

本轮没有开展家长访谈、儿童可用性测试或教学效果研究，不据此宣称降低了多少学习成本、适合所有年龄，或能够提升多少空间能力。布局与交互回归结果以项目测试和更新后的截图为准。

建议下一轮邀请实际使用者完成短任务：独立选择一个模式；切换方向比较同一模型；画完三幅视图并修正错误；搭建后保存并恢复作品。家长或老师可另试一次带讲解的共同操作。观察是否找得到切换入口、是否混淆观察方向、是否需要频繁回看模型、是否误触格子，以及文件操作是否容易理解。

若手机仍频繁往返模型和网格，再评估小模型预览或可展开对照区；先验证真实需要，再增加固定面板，避免进一步占用作答空间。

## 设计方向与仍需讨论的取舍

产品主轴是“同一个立体模型，可以观察、验证、推理和编辑”。功能入口按操作分类；家长、教师、学生无需先选择身份。主界面保留直接操作，可选讲解提示提供使用方法。

| 设计层面 | 当前判断 | 依据与取舍 |
| --- | --- | --- |
| 模式组织 | 观察、练习、搭建平级；当前观察模型可直接进入绘图 | 自动更换模型会打断正在进行的比较或讲解；也应保留另起随机题的自由 |
| 桌面对照 | 保留立体模型与三幅投影同时可见 | 三视图本身就是比较关系，应优先利用大屏的并列空间 |
| 手机作答 | 先使用逐幅切换，保留每幅图纸，提供回看入口 | 大格子方便点按；代价是无法同时比较三幅完整投影。是否需要可折叠的小模型预览，应结合真实主用设备判断 |
| 视觉层级 | 模型与当前动作优先，作品文件和记录次之 | 保存、导入、导出等低频操作不应和检查、增减积木争夺注意力 |
| 反馈语义 | 区分漏填、多填、参考答案和独立完成 | 反馈需要指出下一步如何操作，不以总分代替理解；剖切明确只影响3D展示，完整投影保持不变 |
| 默认内容 | 当前以简单台阶示范入场，随时可换随机模型或进入搭建 | 固定示范便于初次理解；经常创作的人可能更希望继续上次作品。默认入口尚需使用习惯反馈 |

最值得向实际使用者确认的是主用设备及最常进入的模式。这直接决定手机是否需要固定模型预览，以及首页优先展示范例、随机模型还是最近作品。配色、圆角或加入更多动画不会解决这两个问题，应在主要操作路径确定后再细化。

代码对应：`index.html` 中的 `projection-tabs`、`parent-guide` 和 `section-note`；`css/style.css` 中的小屏投影选择和搭建盘布局；`js/app.js` 中的 `selectProjection`、`checkPractice`、`restoreBuild` 与 `learn-practice` 事件。审查参考了 [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md) 的焦点、触摸目标、反馈与动态效果规则，按本项目表面选择适用项。
