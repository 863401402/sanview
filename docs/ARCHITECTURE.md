# 架构说明

本文对应 1.2.0。Sanview 是通用三视图与空间探索工作台，采用无后端、无运行时包依赖的静态应用架构。Three.js 与 OrbitControls 以固定版本文件随仓库分发；Playwright 只用于开发测试。浏览器加载各逻辑模块后，由 `app.js` 协调页面、3D 场景和用户交互。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| `js/coordinates.js` | 坐标语义、三视图投影、空间边界和有支撑的随机结构 |
| `js/model-library.js` | `stairs`、`corner`、`towers` 三个教学范例，按空间尺寸生成坐标 |
| `js/learning-state.js` | 题目结果去重与统计、作品规范化、JSON 导入导出、安全存储封装 |
| `js/section-geometry.js` | 切平面与立方体求交、交点去重和截面排序 |
| `js/voice-library.js` | 教学语音文本、变体和同源 MP3 路径 |
| `js/app.js` | 模式切换、DOM 和 Three.js 渲染、输入、搭建历史、可选讲解提示、教程与语音调用 |
| `css/style.css` | 响应式布局、可交互状态和可访问性表现 |

纯逻辑模块通过浏览器全局对象和 CommonJS 导出同一 API，便于在 Node.js 中直接测试。新规则应优先放入对应独立模块；`app.js` 负责把输入和渲染连接起来，避免重新实现一套投影、校验或练习统计规则。

## 模式与显示状态

观察、练习、搭建是平级模式，可分别进入。练习含画三视图与按三视图还原两种任务；推荐学习顺序不应成为路由、解锁条件或强制课程。`parent-guide` 只承载可选的“讲解提示（家长/老师）”，不表示用户身份或年龄限制。教程通过“使用帮助”按需打开，不在首次进入时自动弹出。

默认观察示范为简单难度、边长 4 的三层台阶。“用这个模型练习”将当前观察结构传入绘图练习，保留尺寸与积木坐标；新建随机题是另一个操作。

可选入门演示在同一个模型上依次呈现前、左、上三个方向，不在每一步重新生成结构。演示状态与模式权限分开，退出演示后仍可直接进入任何模式。

手机逐幅选择 `front`、`left`、`top`，并提供回看模型入口。视图选择仅影响显示，不应清空各幅图的作答数据。新题初始化与显示切换分开处理，使独立练习和共同讲解都能保留上下文。

桌面保持模型与投影对照，手机保留完整操作。检查控件位于投影操作区；工作区状态消息置于 `.stage` 内。全屏以整个 `#workspace` 为目标，保留模型、投影与检查控件；不支持原生全屏时展开同一工作台。对话框也须位于当前全屏子树，关闭后恢复合理焦点。

## 输入与作答边界

3D 拾取和俯视搭建盘采用一致的工具语义：鼠标主键、触摸与键盘执行当前 `buildTool`；鼠标右键只为本次操作提供减少指令，不调用全局工具切换。工具按钮选中态、悬停预览和实际操作必须一致，不能在按下主键时隐式切回增加。

参考答案使用独立只读弹窗渲染，与可编辑作答网格分开。打开、关闭参考窗口不能把答案写回 `practiceDrawn`，也不能让旧的漏填、多填状态冒充参考答案的检查结果。

“清空三幅”在清空前保留当前三幅图纸快照，“撤销清空”仅恢复作答内容。开始重新涂格或换题后，这份恢复快照失效。它与搭建的 80 步历史分开，不恢复或降低本题已有的辅助学习标记；刷新后也不会保留。

对于未完成且已有作答的练习，更改尺寸、难度、练习类型、离开练习和新题操作共用离开确认逻辑。取消必须保持题目标识、结构、尺寸、图纸及辅助标记不变，不能先修改状态再询问。确认规则不应阻断空白题或已完成题的正常导航。

## 坐标与投影

所有模块使用以下约定：

| 轴 | 正方向 | 画面含义 |
| --- | --- | --- |
| X | 左到右 | 正视图、俯视图的画面右方 |
| Y | 下到上 | 正视图、左视图的画面上方 |
| Z | 后到前 | 左视图的画面右方；俯视图从上到下 |

正视图观察者位于 `+Z`，左视图位于 `-X`，俯视图位于 `+Y`。投影数组按 DOM 顺序输出：从上到下、每行从左到右。遮挡时保留对应观察方向最靠前的积木颜色；判题比较格子是否有投影，不比较颜色。

空间为边长 3–8 的立方网格，默认边长 4。坐标为从 0 开始的整数，非底层积木必须有正下方同列积木支撑。添加时检查支撑，删除时须先移除同列上层积木。固定范例、随机题和导入作品使用相同规则。

随机题的积木数量由空间尺寸与四档难度共同决定。还原任务分别比较正视图、左视图和俯视图，不要求坐标集合等于出题模型，因此相同投影的多个合法结构都能通过。

## 状态分层

| 状态 | 保存位置 | 生命周期 |
| --- | --- | --- |
| 当前模式、视图选择、相机、剖切、作答网格 | 页面内存 | 当前页面；显示切换保留图纸 |
| 当前题目的清空前图纸快照 | 页面内存 | 用于撤销清空，不跨页面保存 |
| 搭建撤销与重做 | 页面内存 | 当前搭建会话，最多 80 步撤销 |
| 最近题目结果 | `localStorage` 的 `sanview.progress.v1` | 当前来源、当前浏览器；最多 200 题 |
| 最近一件自由作品 | `localStorage` 的 `sanview.build.v1` | 当前来源、当前浏览器；后续保存替换旧作品 |
| 教程已读标记 | `sanview-tutorial-seen-` 前缀的键 | 当前来源、当前浏览器 |

搭建历史快照同时包含 `size` 与 `cubes`，因此缩小空间后的撤销能恢复尺寸及被裁去的积木。撤销后进行新操作会清空重做分支。刷新页面可恢复最近保存的自由作品，但不会恢复撤销历史或尚未提交的练习题。

观察和练习的题目模型与自由作品分开管理，切换学习任务不应覆盖自由作品。自由搭建发生有效变化后保存；JSON 导入先完成全部校验，再替换当前作品，并把替换前状态纳入撤销历史。

## 练习统计约定

`createProgress()` 返回 `{ version: 1, records: [] }`。每条记录包含 `questionId`、`mode`、`solved` 和 `assisted`；模式为 `draw` 或 `challenge`。

`recordResult(progress, result)` 返回新对象，不修改传入状态。同一模式、同一题目编号的重复检查只保留一条；后续正确可把未完成升级为完成，后续错误不会撤销已有通过状态。使用明确的辅助观察按钮或查看参考答案会使 `assisted` 持续为真，后续提交正确也不计独立完成。关闭参考窗口、恢复图纸或撤销清空不得重置这一标记。

`summarizeProgress(progress)` 返回总计与分模式的 `attempted`、`solved`、`independent`。最近更新的题目保留在记录末尾，超出 200 题时移除最早未更新的记录。因此 UI 必须写“最近 200 题内”，不能写终身累计、考试分数或能力评级。

## 作品格式与校验

```json
{
  "version": 1,
  "size": 3,
  "cubes": [[0, 0, 0], [0, 1, 0], [1, 0, 0]]
}
```

每个三元数组依次为 `[x, y, z]`。`normalizeBuild` 验证版本、整数尺寸、整数坐标、边界、重复位置、最多 512 块以及正下方支撑，返回独立副本并按 Y、Z、X 排序。空作品合法；附加字段不进入规范化结果。

`parseBuild` 拒绝过大的文本和无效 JSON，校验失败返回清晰中文错误；文件入口在读取前限制为 64 KB。`serializeBuild` 先校验再生成 JSON。导入在浏览器内读取，不上传文件，也不执行文件内容。

`createStorage(storage)` 的读取失败分别返回空练习记录或 `null` 作品，写入和清除返回布尔结果。配额不足、存储禁用或损坏数据不会中断练习。获取 `window.localStorage` 本身也可能抛错，调用方应先捕获，再把实例或 `null` 传入封装。界面保留内存状态、说明未能持久保存，并提供作品导出。

## 剖切与音频

剖切使用 Three.js 局部裁剪平面隐藏一侧几何体，截面由 `section-geometry.js` 计算交点、排序，再由 `app.js` 生成封口和轮廓。剖切仅影响显示，投影、判题和作品保存始终使用完整模型。

音效由浏览器合成，教学 MP3 从同源静态目录加载；失败时可回退到浏览器中文朗读。MiMo 只在维护者的语音生成脚本中调用，不是应用运行依赖。浏览器朗读是否联网取决于浏览器、系统及语音提供方，见 [隐私说明](../PRIVACY.md)。

帮助教程直接使用系统 `speechSynthesis` 朗读当前步骤文字，遵守静音状态，避免播放与新控件语义不一致的旧教程音频。其他预录语音会过滤依赖“左边/右边”页面布局的变体，避免手机布局变化时指错位置；音频库文件仍保留。

常规语音调用仍须核对屏幕文案、语音目录 `text` 与实际音频。既有录音不会因为调用处的备用文字改变而自动更新；修改任务术语时应同时验证选中的录音和失败回退文本。

## 开发服务与发布

`npm start` 调用 `scripts/serve.js`，默认仅监听 `127.0.0.1:4173`，只提供应用运行所需的静态路径，并限制越界路径与非读取请求。它用于本地开发；对外发布使用 `_site/` 或专门的静态托管服务。

`npm run build` 调用 `scripts/build-site.js`，把发布所需文件整理到 `_site/`，不把整个工作目录作为部署物。源码备份、测试产物、依赖目录和本地配置不能进入公开站点。分发需保留 [第三方声明](../THIRD_PARTY_NOTICES.md) 与相应许可证。

GitHub Actions 使用 `.github/workflows/ci.yml` 串联验证、构建和 Pages 部署；`main` 的验证及构建成功后才可进入部署阶段。仓库地址为 [863401402/sanview](https://github.com/863401402/sanview)，Pages 地址为 [积木三视图实验室](https://863401402.github.io/sanview/)。工作流和文档中的目标地址不代表某次部署已经成功，发布需核查实际结果。

`main` 的分支保护已通过 GitHub API 确认为 `protected=true`，期望配置保存在 [main-protection.json](../.github/main-protection.json)。合并要求 GitHub Actions App `15368` 提供的 `check` 成功，且分支与最新 `main` 同步；管理员同样受限，禁止强推与删除，要求线性历史及讨论全部解决。

配置文件记录期望规则，不会因提交文件而自动修改 GitHub 设置；保护规则的变更还需要实际应用并重新核对 API 状态。

修改通过分支和 PR 进入 `main`，采用 squash merge。当前配置要求 PR，但所需人员批准数为 0，避免个人维护仓库必须依赖第二位审核者；这不会取消 CI 与讨论解决要求。`deploy` 仅在合并后的 `main` 执行，不作为 PR 的必需检查，以免形成“合并前必须先部署”的循环依赖。

## 验证边界

`npm run check` 覆盖语法与单元测试，`npm test` 进一步验证真实浏览器流程。通过 `SANVIEW_BROWSER` 可指定已有 Chrome 的绝对路径，无须另行下载浏览器。功能、布局或输入变更需要检查桌面与移动端截图；自动化 Chromium 结果不替代 Safari、微信内置浏览器或真实触屏设备的实测。
