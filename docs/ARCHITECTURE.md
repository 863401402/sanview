# 架构说明

积木三视图实验室是无构建步骤的静态应用。浏览器按顺序加载 Three.js、OrbitControls、坐标模块、语音清单和应用主逻辑。

## 模块职责

- `js/coordinates.js`：与 DOM 和 Three.js 无关的坐标、投影和随机结构算法，可直接在 Node.js 中测试；
- `js/section-geometry.js`：切平面与立方体的求交、去重和截面顶点排序；
- `js/app.js`：模式状态、Three.js 场景、DOM 渲染、输入事件、教程和语音播放；
- `js/voice-library.js`：语音场景、旁白文本及静态 MP3 路径；
- `css/style.css`：桌面、移动端、交互状态和可访问性样式；
- `tests/coordinates.test.js`、`tests/section-geometry.test.js`：投影、随机结构和截面几何不变量；
- `tests/e2e.test.js`：真实浏览器中的模式切换、搭建、投影、画布和响应式行为。

## 坐标约定

所有模块必须使用同一套右手坐标语义：

| 轴 | 正方向 | 数组或画面含义 |
| --- | --- | --- |
| X | 左到右 | 正视图和俯视图的画面右方 |
| Y | 下到上 | 正视图和左视图的画面上方 |
| Z | 后到前 | 左视图的画面右方，俯视图由上到下 |

观察者位置：正视图位于 `+Z`，左视图位于 `-X`，俯视图位于 `+Y`。投影数组均按 DOM 顺序输出，即从上到下、每行从左到右。

更改观察方向或网格排列时，必须先更新 `coordinates.js` 的约定和单元测试，再同步 3D 相机、方位标签与教程文案。

## 结构与判定

随机题由 `generateAdaptiveStructure` 生成。数量范围同时取决于空间边长和四档难度，非底层积木必须有正下方支撑。

还原积木任务不比较方块坐标集合，而是分别比较正视图、左视图和俯视图。只要三幅投影与目标一致就判定成功，因此允许多个空间结构成为正确答案。

## 剖切渲染

剖切功能使用 Three.js 局部裁剪平面隐藏一侧几何体。`js/app.js` 同时计算平面与每个立方体 12 条边的交点，将结果排序为截面多边形，并生成着色封口和轮廓线。剖切状态仅属于显示层；积木坐标集合、三视图计算、判题和搭建历史始终使用完整模型。

## 状态与隐私

应用状态只存在于当前页面内。唯一跨页面刷新的状态是四个教程是否看过，使用 `localStorage` 保存，不包含题目结果或个人信息。预生成语音从同源静态资源加载；MiMo 只在维护脚本中使用。

## 验证边界

纯算法、语音资源和语法检查应通过 `npm run check` 完成，不启动浏览器。涉及 Three.js、布局、指针或触摸交互的改动需要运行 `npm run test:e2e`，并人工检查桌面与移动端截图。
